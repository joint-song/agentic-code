**skill 可用性验证：**
1. [如果未激活则加载] `.agents/skills/coding-rules/SKILL.md`
2. [如果未激活则加载] `.agents/skills/testing/SKILL.md`

**加载协议：**

- 步骤 4: 如果 `testing/SKILL.md` 未激活 → 执行 **阻塞性读取**

**关键**：在所有必要 skills 确认激活之前，无法执行质量检查。

- 在代码审查期间

## 执行指南

### 1. 构建验证

运行项目构建：
- 确保编译成功
- 检查警告
- 验证输出产物
- 确认依赖已解决

*注意：构建命令是特定于语言的。请检查 `testing/SKILL.md`*

### 2. 测试执行

**测试类别**
- 单元测试：单个函数
- 集成测试：组件交互
- 端到端测试：完整工作流
- 性能测试：速度和资源
- 安全测试：漏洞检查

**测试覆盖率**
- 最低：80% 代码覆盖率
- 关键路径：100% 覆盖率
- 边缘案例：已记录并测试

### 3. 代码质量检查

**静态分析**
- Linting：要求0个错误
- 代码格式：风格一致
- 语言检查：无错误 (静态类型，风格等)
- 复杂度：在限制范围内

**代码审查标准**
- 可读性：自文档化
- 可维护性：易于修改
- 效率：无明显问题
- 安全性：遵循最佳实践

### 4. 质量标准

| 方面 | 标准 |
|--------|----------|
| 函数 | ≤ 30行 |
| 复杂度 | ≤ 10 圈复杂度 |
| 重复率 | < 5% |
| 测试时间 | 总计 < 30秒 |
| 构建时间 | < 2分钟 |
| 注释 | 仅用于非显而易见的部分 |

### 5. 安全验证

检查：
- 存在输入验证
- 防止 SQL 注入
- XSS 防护
- 认证正确实现
- 授权检查到位
- 敏感数据已加密
- 密钥未硬编码

### 6. 性能验证

验证：
- 响应时间可接受
- 内存使用合理
- 数据库查询已优化
- 在需要的地方实现了缓存
- 没有不必要的循环
- 异步操作正确

### 7. 文档检查

确保：
- README 已根据需要更新
- API 文档为最新
- 复杂逻辑已解释
- 配置已记录
- 设置说明清晰
- 重大变更已注明

## 质量流程

```
1. 运行构建 → 必须成功
2. 运行测试 → 必须全部通过
3. 检查覆盖率 → 满足最低要求
4. 运行 linter → 0个错误
5. 检查格式 → 一致
6. 审查安全性 → 无问题
7. 测试性能 → 可接受
8. 更新文档 → 最新
```

## 常见问题与修复

| 问题 | 可能原因 | 修复 |
|-------|-------------|-----|
| 构建失败 | 缺少依赖 | 安装依赖 |
| 测试失败 | 逻辑错误 | 调试并修复 |
| Lint 错误 | 风格违规 | 应用格式化 |
| 静态分析错误| 语言违规 | 修复定义/签名 |
| 测试缓慢 | 没有模拟 | 添加测试替身 |
| 安全警告 | 旧的依赖 | 更新包 |
