# 集成测试 & E2E 测试设计/实现规则

## 测试类型和限制

| 类型 | 目的 | 限制 |
|------|---------|-------|
| 集成测试 | 组件交互验证 | 每个功能 3 个 |
| E2E 测试 | 关键用户旅程验证 | 每个功能 1-2 个 |

## 行为优先原则

### 可观察性检查 (全部为“是”则包含)

| 检查 | 问题 | 如果为“否” |
|-------|----------|-------|
| 可观察 | 用户能观察到结果吗？ | 排除 |
| 系统上下文 | 是否需要多个组件的集成？ | 排除 |
| 可自动化 | 能在 CI 环境中稳定运行吗？ | 排除 |

### 包含/排除标准

**包含**: 业务逻辑准确性、数据完整性、用户可见的功能、错误处理
**排除**: 外部实时连接、性能指标、实现细节、UI 布局

## 骨架规范

### 必要的注释格式

每个测试骨架 **必须** 包含：
- **AC**: 原始验收标准文本
- **ROI**: 计算出的分数，包含业务价值和频率
- **Behavior**: 触发器 → 过程 → 可观察结果的格式
- **Metadata**: `@category`, `@dependency`, `@complexity` 注解

## 实现规则

### 行为验证

| 步骤类型 | 验证目标 |
|-----------|---------------------|
| 触发器 | 在测试设置中重现 (准备阶段) |
| 过程 | 中间状态或函数调用 |
| 可观察结果 | 最终输出值 (返回值, 错误消息, 日志输出) |

**通过标准**: 如果“可观察结果”被验证为返回值或模拟调用参数，则测试通过

### 集成测试模拟边界

| 判断标准 | 模拟 (Mock) | 实际 (Actual) |
|-------------------|------|--------|
| 是测试目标的一部分吗？ | 否 → 可以模拟 | 是 → 需要实际对象 |
| 存在外部网络通信吗？ | 是 → 需要模拟 | 否 → 推荐实际对象 |

### E2E 测试执行条件

- 仅在所有组件实现后执行
- 不使用模拟 (需要完整的系统集成)

## 审查标准

### 骨架与实现的一致性

| 检查 | 失败条件 |
|-------|-------------------|
| 行为验证 | “可观察结果”没有断言 |
| 验证项覆盖 | 列出的验证项未包含在断言中 |
| 模拟边界 | 在集成测试中模拟了内部组件 |

### 实现质量

| 检查 | 失败条件 |
|-------|-------------------|
| AAA 结构 | 准备/执行/断言 (Arrange/Act/Assert) 的分离不清晰 |
| 独立性 | 测试之间共享状态，依赖执行顺序 |
| 可复现性 | 依赖于日期/随机数，结果不一致 |
| 可读性 | 测试名称与验证内容不匹配 |
